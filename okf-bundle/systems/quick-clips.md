Quick Clips is the pattern-extraction feature that makes Clipless "read" clips. Since the quick look redesign (1.9.0, 2026-08-23) scanning is one pure function, `scanText(text, terms)` in `src/shared/scan.ts`, and it runs in the renderer with no IPC. The clips window renders every match as a chip and the pinned set drives the launch tray (see [Tools Launcher replaced by quick look](../decisions/tools-launcher-window-replaced-by-quick-look-and-pin-tray.md)); the settings Tools tab previews with the same function (see [Settings window redesign](../decisions/settings-window-redesign.md)). The choices behind this: [Quick look engineering calls](../decisions/quick-look-engineering-calls.md).

How it works (verified in source):

- **Search terms** are regex patterns (stored in `templates.enc` via [Secure Storage](../systems/secure-storage.md)), each with an `enabled` flag and ordering. Users manage them in Settings > Tools, where every term has an enabled toggle.
- `scanText` compiles each pattern once with flags `gd` (`hasIndices`), so every named group carries `[start, end]` and chips know where to sit. It collects **named capture groups only**: a match with no named groups produces nothing, so a search term MUST use `(?<name>...)` groups. Group names are the token vocabulary shared with tool URLs and [Templates](../systems/templates.md). Disabled terms are skipped; a pattern that does not compile is skipped and reported in `ScanResult.errors`; an empty match advances `lastIndex` so a pattern that can match the empty string cannot loop. Matches are sorted by start, `groups` in order of first appearance, and overlapping matches from different terms are all kept; the row and the reader render the earlier one.
- The clips window holds a `ScanIndexProvider` (`src/renderer/src/providers/scan.tsx`): the Quick Clips config (search terms, tools, templates, `groupColours`) loads once, a `Map<clipId, { contentKey, result }>` caches one scan per clip and re-scans only when the clip's text changes, and the whole cache clears when the main process broadcasts `quick-clips-config-changed` after any search term, tool, template or `groupColours` write. Nothing is scanned until the terms have loaded. Clips above 256 KB of text are scanned in an idle callback; `getScan` returns null until then. `slotFor(group)` gives the colour bucket slot; components set `--gc: var(--slot-N)` and never a hex. The settings window mounts the same provider; its Tools tab reads `terms`, `tools`, `templates`, `groupColours` and `loaded` from it.
- What is scanned is `clipText(clip)` (`providers/clips/utils.ts`): the extracted `text` for html and rtf clips (produced in the main process at capture, see [clipboard monitoring](../systems/clipboard-monitoring.md)), `title + '\n' + url` for bookmarks, the content otherwise, nothing for images. A bookmark's URL is a chip only when a term matches it (spec section 10 wins over rule 6's wording).
- Readers of the scan in the clips window: `CollapsedLine` (the row's chips and search marks, first 2000 characters only), the reader's `Content` (per-line Prism tokens through `refractor`, split at match offsets in `components/quick-look/tokens.ts`), the side column, the tray and template readiness. The pure helpers `visibleMatches` and `markHits` live in `components/clips/clip/matches.tsx`. Pins are a `group|value` map in the clips provider (`providers/clips/pins.ts`), memory only; `usePinPruning` drops pins whose key is in no clip's scan and names why (after the edit, deleted with clip N, rotated out of the list, after the search terms changed).
- In settings, the search term editor scans the one pattern under edit against the sample text (`scanText(sample, [{ id, pattern }])`) and shows chips before Save, so chips and previews cannot disagree; the tool and template editors use `valuesByGroup` of the sample's scan. Pattern validation (`components/settings/tools/model.ts`) blocks Save when the regex does not compile, matches the empty string, has no named group, or uses a reserved `c1`-style name.
- `BUILTIN_PATTERNS` is one library in `src/shared/builtinPatterns.ts` (eight entries, each with a name, a short description and a pattern; IPv4 Address, Email Address, Domain Name, Phone Number, URL, MAC Address, IPv6 Address, UUID; group names `ip`, `email`, `domain`, `url`, `phone`, `mac`, `guid`, `ipv6`). It never runs on its own; the settings "start from" page copies an entry in as a search term, shows "already added" by matching the pattern body (so a term added from the old library under another name still counts), and re-enables a disabled duplicate instead of adding it twice. The TLD list behind the domain pattern is `src/shared/tlds.ts`.
- `groupColours` (group name to colour bucket slot 0 to 11, never a hex) lives beside the search terms in `templates.enc`; the bucket and the resolver (override, then named default, then lowest free slot) are in `src/shared/groupColours.ts`. Save drops an entry whose group appears nowhere (`src/main/storage/group-colours.ts`). The theme provider sets `--slot-0` to `--slot-11` on the root element from the pair that matches the theme. The settings Bucket edits the map per group through `group-colours-set`.
- Tool fan-out is `buildToolUrls` in `src/shared/tools.ts`; the tray, the reader's Launch button and the settings preview all count tabs with it (`components/tray/useToolUrls.ts`; `components/settings/tools/resolve.ts` mirrors it to colour each value and its test checks the two agree). Tabs open through the `open-external-urls` IPC, which accepts http and https only. Readiness wording is `src/shared/readiness.ts`.

Gone with the redesign: the main-process `scanTextForPatterns`, the `quick-clips-scan-text` IPC, the settings Test Patterns tab, the [Tools Launcher](../systems/tools-launcher.md) window and its IPC, preload methods, `PatternMatch` and `base.css`.

Quick Clips configs (search terms, tools, templates, `groupColours`) export as version `2.0.0` and import with a mode, `merge` or `replace`; the settings Tools tab's footer links show the counts and the JSON on export and preview the counts and groups on import. See `docs/specs/quick-look-redesign.md` sections 14 and 17.
