Clipless redesign: clips window, quick look, settings

One page for the whole redesign. The Tools Launcher window goes away and its job moves into the clips window as chips, a quick look reader and a launch tray; the Settings window is rebuilt around the same capture-group vocabulary, with a left rail, a master-detail Tools tab, and General and Hotkeys tabs on the same shell. Each section below embeds the live prototype for that part, in the order a user meets them. Every prototype is a plain HTML file with no build step; the "open full page" link on each frame shows it on its own, and the theme button at the top switches all of them at once. The spec is quick-look-redesign.md; the review of what it missed is quick-look-outliers.md.

1. Clips window and quick look locked, spec 1 to 13

Matched values are chips in each row; clicking one pins it. Space or the eye opens the reader over the dimmed list, inside the window. The launch tray under the list turns the pinned set into browser tabs or template text, and always says how many tabs before it opens them.

3. Settings: Tools tab locked, spec 14

Where search terms, tools and templates are made. A list pane of every item with a health dot and a swatch strip, and an inspector with Edit and Uses: sample text pinned above the editor, live previews (chips for a term, every resolved URL and the tab count for a tool, generated text for a template), and the fix beside any token nobody produces. Colour belongs to the capture group, chosen from a bucket of twelve slots that each carry a dark and a light value.

4. Settings: shell, General and Hotkeys locked, spec 15, variation C

The General and Hotkeys tabs take the Tools tab's shell so the three read as one window: a 132px left rail with the version at the bottom, a 900 x 600 window that holds at 720 x 440. General applies each control immediately with its own inline status; Hotkeys records a shortcut by clicking the keycap and pressing the keys. Five variations are on the page; C, the dense no-scroll grid, is the one chosen, and the frame below opens on it.

Rules that hold everywhere

  • Icons are the FontAwesome set the app registers in fontawesome.ts. No emoji.
  • Both themes. One variable set per prototype, swapped by the theme button.
  • Rendered HTML never runs code: inert parse, allowlist, sandboxed frame with default-src 'none'.
  • Anything that opens more than one tab says the count first; every clipboard write toasts.
