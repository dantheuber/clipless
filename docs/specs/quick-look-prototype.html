Quick look, polished: the G5 clip reader refined

G5 from the last round: Space (or the eye) opens a reader over the dimmed list, drawn inside the Electron window. This version fixes the content column so it scrolls, drops the redundant "pinned" list from the side column, and tightens everything else: a real line-number gutter, matches grouped by capture group with hover-to-locate, wrap toggle for long lines, copy and edit in the header, and a footer that shows what the pins add up to without listing them again. Two frames below: the default 900x520 window, and a 300px-tall window to show the reader still fits and still scrolls. Clicking a launch target shows a toast instead of opening tabs.

What changed from G5

  • Content scrolls. The left column is a flex column with min-height: 0 and the content pane is flex: 1; overflow: auto. Clip 5 is a 30-line log and clip 6 is a 14-line Python file so you can see both the vertical scrollbar and, with wrap off, the horizontal one. The gutter sticks to the left edge during horizontal scroll.
  • No pinned list. The side column is just the matches, grouped. A pinned chip looks pinned (solid border, tick), so state is visible where you set it. The footer says "3 pinned" and offers the launch button; the full tray is one click away and still under the list when the reader closes.
  • Matches grouped by capture group. Each group has a colour swatch, a count, and a "pin all" link for that group alone. Values that occur more than once show "x2". Hovering a match outlines every occurrence in the content and scrolls the first one into view, so you can find it before you pin it.
  • Header carries everything that acts on the whole clip. Prev/next with "2 / 6", the clip number and type, then pin all (with a pinned/total count), copy clip, edit, wrap, close. Pin all and edit show an on-state when active.
  • Edit is the same surface, scrolled the same way. The editor replaces the content pane and inherits its size. Esc leaves edit first, then closes the reader. Committing updates the collapsed line and re-scans.
  • Templates copy from the footer. Every template with named tokens is listed next to the pinned count. One whose tokens are all pinned is a solid yellow pill; clicking it generates the text and copies it, with a toast saying which values it used. One that is missing tokens is dimmed with "needs ticket" on it; if the current clip contains the missing values, clicking the dimmed pill pins them from this clip (first occurrence) and the pill turns ready. If the clip does not have them, the pill is inert and the tooltip says to pin from another clip. t copies the first ready template. See Templates in the reader.
  • Entrance is visible. A 120ms scale-and-fade so the reader clearly comes from the list rather than just appearing. Focus moves into the reader on open and returns to the row on close.

Keyboard



  Spaceon a focused row, open quick look. While open, Space scrolls the content (browser default), as it should in a reader.
  ↑ ↓previous / next clip, skipping clips with no content. Wraps at neither end; the arrow buttons grey out instead.
  ppin all values in this clip. Press again to unpin them all. The header shows "3/5" when some are pinned.
  etoggle edit. Esc leaves edit without closing the reader. Enter commits as it does in the row editor today, Shift+Enter inserts a newline.
  ccopy the whole clip to the clipboard, same as clicking the row number in the list.
  tcopy the first ready template. With none ready, a toast says what to pin. Click a specific pill in the footer to choose among several ready templates.
  wtoggle wrap for long lines. Remembered per session.
  Escclose. Focus returns to the row that was open, so ↑↓ in the list continue from there.




Side column rules


    
  
  • Groups are ordered by first appearance in the clip, not alphabetically, so the column reads top to bottom the way the text does.
    • 
  
  • A value that appears more than once in the clip is listed once with "xn". Pinning it pins every occurrence, and the tray dedupes by value anyway.
    • 
  
  • "pin all" on a group pins that group only. The header's pin-all covers every group. Both are toggles: if everything they cover is already pinned, they unpin.
    • 
  
  • Hovering a value outlines its occurrences in the content and scrolls the first into view. Hovering a chip in the content lifts its row in the side column. Neither hover pins anything.
    • 
  
  • With no matches, the column says so in one line and the pin controls grey out. The reader still works as a plain viewer for clips with nothing to extract.
    • 




Templates in the reader


The launch button and the template pills sit together in the footer because they are the same kind of thing: outcomes of the pinned set. Launch opens tabs from it; a template copies text built from it. Three rules:


    
  
  1. Readiness comes from pins, not from the clip. "Incident Summary" needs {ticket}, {ip} and {email}. It is ready when all three groups have a pinned value, whichever clips they came from. This is the cross-clip case the old launcher window could not do: ticket from clip 2, IP from clip 5, email from clip 6, one copy.
    2. 
  
  2. Not-ready pills are a shortcut, not a dead end. A dimmed pill names what is missing. If the clip you are reading has that value, clicking the pill pins it (first occurrence) and the pill becomes ready; a toast says what got pinned. If the clip does not have it, the pill is inert and the tooltip points you to another clip. In the 300px frame not-ready pills are hidden to save space; ready ones always show.
    3. 
  
  3. One value per token. With two IPs pinned, the template uses the first one pinned and the tooltip and toast both say so ("ip 203.0.113.42 (first of 2)"). To use the other, unpin the first. This replaces the old launcher's disabled-with-warning state, which blocked instead of choosing.
    4. 



Copying is a clipboard write with no visible result, so the toast is not optional: it names the template, the character count, and the values used. Clip templates that use only positional tokens ({c1}, {c2}) are not shown here; they do not depend on pins and belong in the context menu, as argued in the earlier inline-variants document.



Implementation notes


    
  
  • Layout. The reader is position: absolute; inset: 38px 4% 44px 4% inside the window's root element, so it is bounded by definition. Inside: a column flexbox (header, body, footer) where body is flex: 1; min-height: 0 and a two-column grid. Each grid column is itself a column flexbox with min-height: 0, and the scrolling panes are flex: 1; overflow: auto. The min-height: 0 at every level is what was missing in G5.
    • 
  
  • Lines, not a pre. Content is rendered as one grid row per line (gutter cell, text cell) so line numbers are real elements, the gutter can be sticky during horizontal scroll, and lines with matches can be tinted. This is also what lets "scroll the first occurrence into view" work.
    • 
  
  • Prism tokens with chips inside. Run Prism on the clip text, then walk the token tree splitting text nodes at match offsets (from the d-flag regex) to wrap values in chip spans. Tokens are never split across lines, so split into lines first, then tokenise per line with Prism's tokenize rather than highlight, keeping multi-line token state out of scope.
    • 
  
  • Editor. Reuse the existing textarea plus Prism overlay, sized to the same pane. Chips are not rendered in edit mode. On commit: update clip, re-scan, re-render the reader in place (do not close it).
    • 
  
  • Focus and accessibility. The reader is role="dialog", gets focus on open, traps Tab within itself, and returns focus to the originating row on close. The dimmer is aria-hidden and clickable.
    • 
  
  • Pins. Same group|value map in the clips provider as every previous round. The reader reads and writes it; the list chips and the tray re-render from it.
